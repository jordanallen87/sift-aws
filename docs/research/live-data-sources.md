# Live data sources for Sift's Standing Watch feature

Research date: 2026-09-07. Every claim below is sourced with a URL. Where a source is a third-party summary rather than an official page, that is noted — official docs were preferred wherever found.

Sift compares subcontractor bids for a construction job. After the first recommendation, "Standing Watch" wants to keep checking for material changes: a revised bid, a license/insurance status change, new reviews, or a permit requirement change. This document inventories which of those checks can be backed by a real API today, versus which require Tavily-mediated web search, versus which are simply not honestly buildable in a hackathon timeframe.

---

## 1. Tavily API — capabilities, SDK, and monitoring

### Endpoints (current as of Sept 2026)

Tavily's live product surface is five endpoints: **Search, Extract, Crawl, Map, and Research** ([docs.tavily.com quickstart](https://docs.tavily.com/sdk/javascript/quick-start), [npmjs.com/package/@tavily/core](https://www.npmjs.com/package/@tavily/core)).

- **Search** (`tvly.search(query, opts)`) — keyword/semantic web search tuned for LLM consumption. Request params include `search_depth` (`basic`/`advanced`/`fast`/`ultra-fast`), `max_results` (0–20), `topic` (`general`/`news`), `time_range`/`start_date`/`end_date`, `include_domains`/`exclude_domains` (up to 300/150 domains), `include_answer` (LLM-synthesized answer), `include_raw_content`, `country`, `language`. Response: `query`, `answer`, `results[]` (each with `title`, `url`, `content`, `score`, `raw_content?`, `favicon?`), `response_time`, `usage`, `request_id` (fetched directly from the official API reference, [docs.tavily.com/documentation/api-reference/endpoint/search](https://docs.tavily.com/documentation/api-reference/endpoint/search)).
- **Extract** (`tvly.extract(urls)`) — pulls clean markdown/text content from one or more URLs you already have; `extract_depth: "advanced"` for JS-heavy or table-heavy pages.
- **Crawl** — "agent-first" crawl starting at a URL with natural-language `instructions` (e.g., "find all pages about the Python SDK"); still flagged in Tavily's own quickstart as a newer/evolving endpoint.
- **Map** — returns the URL structure of a site without extracting content (site discovery).
- **Research** (`mcp__tavily__tavily_research` in this environment, or `research()` in the SDK) — multi-source, agentic research that returns a synthesized report; **rate-limited to 20 requests/minute** per this environment's own tool description, and costs meaningfully more credits per call (~$0.03–$2.00, per third-party pricing analysis, [coldiq.com/blog/tavily-vs-exa](https://coldiq.com/blog/tavily-vs-exa)).

### Node/TypeScript SDK

- Package: **`@tavily/core`** (MIT license, official, `npm i @tavily/core`), current version 0.7.x, ~393K weekly downloads ([npmjs.com/package/@tavily/core](https://www.npmjs.com/package/@tavily/core)).
- Minimal example:
  ```ts
  import { tavily } from "@tavily/core";
  const tvly = tavily({ apiKey: process.env.TAVILY_API_KEY! });
  const response = await tvly.search("Acme Plumbing LLC reviews Austin TX");
  ```
- A LangChain wrapper also exists (`@langchain/tavily`, exposing `TavilySearch`, `TavilyExtract`, `TavilyCrawl`, `TavilyMap`, `TavilyResearch` as LangChain tools) if Sift's agent runtime uses LangChain-style tool binding ([npmjs.com/package/@langchain/tavily](https://www.npmjs.com/package/@langchain/tavily)).
- The SDK also supports optional `sessionId`/`humanId`/`clientName` headers for attributing calls to a session/user, which is useful for per-case audit trails in Sift's activity log ([docs.tavily.com/sdk/javascript/reference](https://docs.tavily.com/sdk/javascript/reference)).

### Pricing / free tier (Sept 2026)

- **Free tier: 1,000 API credits/month, no credit card required.** Basic search = 1 credit/request; advanced search = 2 credits/request; Extract ≈ 1 credit per 5 URLs; Research ranges much higher (up to ~250 credits for deep multi-source runs) ([uragent.org/tools/tavily](https://uragent.org/tools/tavily), [coldiq.com/blog/tavily-vs-exa](https://coldiq.com/blog/tavily-vs-exa)).
- Paid: **Researcher** $30/mo (~4,000 credits), **Startup** $100/mo (~15,000 credits), Enterprise custom. Pay-as-you-go beyond plan credits: $0.008/credit.
- **Rate limits**: Tavily's own API reference does not publish numeric requests-per-second/minute limits; it documents error codes instead — `429` (rate limit exceeded), `432` (key/plan limit exceeded), `433` (pay-as-you-go limit exceeded) — and directs developers to their dashboard for plan-specific numbers ([docs.tavily.com/documentation/api-reference/endpoint/search](https://docs.tavily.com/documentation/api-reference/endpoint/search)). The Research tool specifically is capped at 20 req/min per this environment's tool spec.

### Best endpoint per Sift use case

| Sift need | Best Tavily endpoint | Why |
|---|---|---|
| (a) "Find recent reviews/complaints about contractor X in city Y" | **Search** (`topic: general`, `time_range: month/year`, `include_answer`) | Search is built exactly for "find current info about X," returns ranked snippets + URLs Sift can cite. Research is overkill (and 20x+ the cost) for a single-fact check; reserve it for deeper due-diligence passes. |
| (b) "Extract the line items from this bid PDF/URL" | **Extract**, if the bid is already hosted at a URL Sift can fetch. If the bid is an *uploaded* local PDF (the far more common Sift case), Extract does not apply — use a Node PDF library or Bedrock Data Automation instead (see §5). | Extract is for URLs it can retrieve itself, not files a user drags into the app. |
| (c) "Monitor for new mentions" | **Search on a schedule Sift owns** (see below) | No native monitoring feature — see next section. |

### Scheduled/monitoring/webhook support: **none native — must poll**

Tavily does **not** offer a first-party scheduled-search, monitoring, or webhook/push feature as of this research. Evidence:
- Tavily's own blog demonstrates "automated monitoring" only by pairing Tavily Search as a *tool* inside a third-party workflow engine (n8n) that supplies its own Schedule Trigger node — the polling/cron logic lives in n8n, not Tavily ([tavily.com/blog/building-autonomous-workflows-tavily-n8n-real-time-web-data-low-code](https://www.tavily.com/blog/building-autonomous-workflows-tavily-n8n-real-time-web-data-low-code)).
- Graphlit's integration similarly builds a "search feed" with a `schedulePolicy` — that recurrence engine is Graphlit's, calling Tavily underneath, not a Tavily-native feature ([graphlit.com/vs/tavily](https://www.graphlit.com/vs/tavily)).
- Competitor Exa explicitly ships a "Monitors" product; Tavily's comparable endpoint list (Search/Extract/Crawl/Map/Research) has no equivalent, confirming the gap is real and not a documentation oversight ([coldiq.com/blog/tavily-vs-exa](https://coldiq.com/blog/tavily-vs-exa)).

**Implication for Standing Watch**: Sift must own the schedule (a cron/interval job or on-demand trigger inside its own Express backend) and call Tavily Search fresh each time, diffing results against the last-seen snapshot stored in SQLite. This is a normal, honest pattern — it is simply not "Tavily pushes us an event," and the demo/docs should say so rather than imply push-based monitoring.

## 2. Contractor licence and insurance verification

There is no unified national database — each state runs its own board with its own data posture ([blog.cobaltintelligence.com](https://blog.cobaltintelligence.com/post/contractor-license-verification-api-complete-guide-construction-lenders)). Findings for 5 representative states:

| State | Board | Machine-readable official access? | Realistic hackathon build |
|---|---|---|---|
| **California** | CSLB (Contractors State License Board) | **No live API.** The "Instant License Check" is an HTML-only lookup form ([cslb.ca.gov/onlineservices/dataportal](https://www.cslb.ca.gov/onlineservices/dataportal)). CSLB *does* publish official **bulk CSV/XLS downloads**: "List by Classification and County" (up to 10 classifications × 10 counties), "List by Classification," a "Master List of Contractors," and "Find a Licensed Contractor" by city/zip — all free, no auth, refreshed on demand from the live database ([cslb.ca.gov/onlineservices/dataportal/ListByCounty](https://www.cslb.ca.gov/onlineservices/dataportal/ListByCounty)). | Download the relevant county/classification XLS once at case-open time (or nightly), parse it into SQLite, and diff status/expiration on each Standing Watch tick. This is a legitimate machine-readable path CSLB itself provides — just batch, not per-lookup real-time. A live single-license check would require scraping the HTML form, which is a ToS-gray area (see §6). |
| **Florida** | DBPR (MyFloridaLicense) | **No official API.** Verification is by name or license number through the MyFloridaLicense web portal/app only ([blog.cobaltintelligence.com](https://blog.cobaltintelligence.com/post/contractor-license-verification-api-complete-guide-construction-lenders)); every "API" found in research is a third-party scraper (Apify actors, RapidAPI wrappers) with no DBPR sanction. | Not honestly buildable as a live per-contractor API check in a day without scraping. Best-effort: use Tavily Search against `myfloridalicense.com` to surface a status page for a human to read, framed explicitly as "search assist," not "verified via API." |
| **Texas** | TDLR (electricians, HVAC/ACR, elevator, water-well) + TSBPE (plumbers, separate agency) | **Yes — real official open-data API.** TDLR license data is published on **data.texas.gov via the Socrata SODA API**, dataset ID `7358-krk7` (Electrical, HVAC, Water Well, Appliance); TSBPE plumbing licenses are a separate Socrata dataset, `qced-zkby`. Both are queryable JSON at `data.texas.gov/resource/<id>.json`, optionally with a free Socrata app token ([github.com/jacquesdjean/texas-contractor-instrument](https://github.com/jacquesdjean/texas-contractor-instrument), confirmed against Socrata's own docs below). Texas has **no statewide license for general contractors or roofers** — only the listed trades are state-regulated ([zabalist.com/tools/license-lookup](https://www.zabalist.com/tools/license-lookup)). | Genuinely a one-day build: `fetch('https://data.texas.gov/resource/7358-krk7.json?$where=...')`, filtered by business name/license number, polled on Standing Watch ticks. This is the strongest "real API" story of the five states. |
| **Washington** | L&I (Labor & Industries) | **Yes — real official open-data API.** Full ~160,000-record contractor registry published on **data.wa.gov via Socrata**, including bond/insurance-adjacent fields; several vendors independently confirm they build directly against "the official Washington State L&I open-data dataset, published on data.wa.gov (Socrata). Public, authoritative, refreshed on business days" ([apify.com/scrapebench/washington-contractor-directory-leads-scraper](https://apify.com/scrapebench/washington-contractor-directory-leads-scraper)). | Same pattern as Texas: direct Socrata JSON query, no scraping. Second-strongest real-API story. |
| **Oregon** | CCB (Construction Contractors Board) | **Yes — real official open data**, though not confirmed to be Socrata specifically. Oregon publishes CCB license records on the **Oregon Open Data Portal** under statutory authority (ORS 276A.350–374), "updated daily" per multiple independent consumers who all cite the same open-data source rather than scraping the CCB's own search page ([ccblookup.com](https://www.ccblookup.com), [data.oregon.gov CDO Service Catalog listing "Construction Contractors Board"](https://data.oregon.gov/stories/s/CDO-Service-Catalog/53ij-4hwu)). One vendor explicitly states "We don't currently offer a public API. The underlying data is available directly from the Oregon Open Data Portal under an open data license" ([ccblookup.com/contact](https://www.ccblookup.com/contact)) — i.e., the portal itself is the real, official, machine-readable source; third parties just don't re-expose it as their own API. | Good one-day build once the exact Oregon Open Data Portal dataset/endpoint is confirmed at build time (the CDO catalog page names "Construction Contractors Board" as a covered dataset but this research did not extract the literal endpoint URL — verify directly against data.oregon.gov before coding). |
| **Arizona** (bonus, requested as option) | ROC (Registrar of Contractors) | **No official API.** roc.az.gov offers only a browser-based search by name/license/ZIP; every ROC data source found is a third-party scraper of the same HTML form ([roc.az.gov](https://roc.az.gov), [jematellhomes.com FAQ](https://jematellhomes.com/faq/how-to-verify-an-arizona-contractor-license-with-the-roc)). | Same as Florida — not a legitimate live-API build in a day. |

### Third-party aggregators

- **Cobalt Intelligence** — commercial "Contractor License Verification API" covering CA/FL/NY-NYC/TX, queries state portals "directly" server-side and returns normalized JSON; positioned at construction lenders, not a dev-friendly free tier documented ([blog.cobaltintelligence.com](https://blog.cobaltintelligence.com/post/contractor-license-verification-api-complete-guide-construction-lenders)).
- **StateLicense.io** — CA/FL/NYC/TX/WA coverage; public preview capped at "10 search or verification requests per IP each UTC day," **no developer API key available yet** ("Dashboard now, developer API later") ([statelicense.io](https://statelicense.io)) — not usable as a real backing API today.
- **Apify actors** (StackRelay, ScrapeBench, Crawler Bros, etc.) — dozens of pay-per-record scrapers exist for every state above. These are unauthorized scrapes of official government portals, not sanctioned APIs; treat as a fallback for a private research spike, never as the honesty-line story in a public demo (see §6).

### Realistic one-day hackathon scope

Build the **Standing Watch license/insurance check on Texas TDLR and Washington L&I only** (real Socrata JSON, no scraping, no ToS risk), verify Oregon CCB's exact open-data endpoint if time allows, and represent California/Florida/Arizona honestly as "search-assisted" (Tavily Search pointed at the official state portal, surfaced to a human to confirm) rather than "verified via API."

## 3. Reviews and reputation

| Source | Official API? | Terms allow "look up reviews for any contractor"? | Cost | Verdict |
|---|---|---|---|---|
| **Google Business Profile API** (mybusiness.googleapis.com) | Yes, official, but scope-restricted | **No.** Explicitly restricted to profiles "you either own or are authorized to manage on behalf of the business owner"; automated/programmatic use by third parties without the owner's own registered project is a listed prohibited practice ([developers.google.com/my-business/content/policies](https://developers.google.com/my-business/content/policies)). Access also requires a manual Basic API Access approval that multiple developers report pending 10–14+ business days or stuck at 0 quota as of Aug 2026 ([discuss.google.dev thread](https://discuss.google.dev/t/business-profile-api-reviews-endpoint-mybusiness-googleapis-com-cant-be-enabled-basic-access-pending-10-business-days/389462)). | N/A — access itself is the blocker | **Not usable** for Sift's use case (looking up a subcontractor's reviews without their consent/ownership access). Do not build against this API. |
| **Google Places API (New)** — Place Details `reviews`/`reviewSummary` fields | Yes, official, general-purpose | Yes — this is the correct Google product for "read public rating/review info for any place." Usage is metered per field-mask SKU; caching/storage of results beyond place IDs is restricted "unless permitted by agreement," and results must carry Google attribution (map or logo + attribution string) ([developers.google.com/maps/documentation/places/web-service/policies](https://developers.google.com/maps/documentation/places/web-service/policies)). | Reviews/ratings fall under the **Enterprise + Atmosphere** SKU, ~$20–25 per 1,000 requests above a small free monthly allotment (1,000 Enterprise Place Details free/mo) ([woosmap.com/blog/google-places-api-pricing](https://www.woosmap.com/blog/google-places-api-pricing)). | **This is the real API to use**, not Business Profile — but budget for the Atmosphere SKU cost and honor the no-long-term-caching / attribution requirements in the UI (show a "via Google" attribution + link, don't persist raw review text indefinitely). |
| **Yelp Fusion / Yelp Places API** | Yes, official | Yes, this is exactly its intended use ("Search Yelp businesses... ratings... reviews"). Free "Fusion" era with unlimited calls ended in **2019**; Yelp now runs a **300 calls/day, 30-day trial** on signup, after which developers must move to a paid tier ($229–$643/mo base, plus $5.91–$14.13 per additional 1,000 calls) ([docs.developer.yelp.com/docs/places-rate-limiting](https://docs.developer.yelp.com/docs/places-rate-limiting), [business.yelp.com/data/products/places-api](https://business.yelp.com/data/products/places-api)). Developers who exceed trial volume without upgrading have had keys disabled ([techcrunch.com/2024/08/02/yelps-lack-of-transparency-around-api-charges-angers-developers](https://techcrunch.com/2024/08/02/yelps-lack-of-transparency-around-api-charges-angers-developers)). | Free for the 300-calls/day, 30-day trial; real cost afterward. | **Usable for a demo within the free trial window** (300/day is plenty for a hackathon), but not a source Sift can promise as "free forever" — document the trial limit honestly. |
| **BBB (Better Business Bureau)** | **No official public API.** A conceptual BBB API spec was discussed in a 2016 blog post (Organization Search, Bulk Retrieval, Push Notifications) but was never shipped as a real product — every current "BBB API" result is a third-party scraper (ScrapingBee, Bright Data, Apify) ([apievangelist.com/2016/...](https://apievangelist.com/2016/08/04/thinking-about-the-better-business-bureau-api-in-context-of-the-overall-api-economy), scraper listings). | N/A | N/A | **Not usable** as a real API. Tavily Search against `bbb.org` is the honest substitute — present it as "search assist," never as "verified BBB rating." |
| **Angi / HomeAdvisor** | **No public API.** Independent API report cards grade both poorly: HomeAdvisor "Grade F" — no public spec, sales-gated where anything exists, unauthenticated internal endpoints only ([supergood.ai/api-report-card/homeadvisor](https://supergood.ai/api-report-card/homeadvisor)). | N/A | N/A | **Not usable.** Tavily Search substitute only. |

**Bottom line for reviews**: the two legitimate, ToS-compliant, general-purpose "look up any contractor's reputation" sources are **Google Places API (New)** and **Yelp Places API (within trial limits)**. Everything else (Google Business Profile API, BBB, Angi/HomeAdvisor) is either scope-restricted to owned listings or has no real API at all — Tavily Search is the pragmatic, honest substitute for those.

## 4. Permits

| Source | Type | Coverage | Cost | Fit for Sift |
|---|---|---|---|---|
| **City/county/state open-data portals (Socrata "SODA" or ArcGIS)** | Official, free, machine-readable | Varies hugely by jurisdiction — many large US cities (Seattle, Chicago, NYC, Austin, etc.) publish permit datasets on Socrata; app tokens are free and raise the throttle to **1,000 requests/rolling hour** ([dev.socrata.com/consumers/getting-started.html](https://dev.socrata.com/consumers/getting-started.html), [dev.socrata.com/docs/app-tokens.html](https://dev.socrata.com/docs/app-tokens.html)). Paging is capped at 50,000 records/page via `$limit`/`$offset`. | Free | Best default: for a specific target city known ahead of a demo (e.g., "does Seattle require a permit for this bathroom remodel," "has a permit been pulled at this address in Austin"), find that city's Socrata permit dataset ID and query it directly — same honest, official pattern as WA L&I/TX TDLR above. Coverage is not nationwide/uniform, so this only works demo-scoped to a chosen city. |
| **Shovels.ai API** | Commercial, but sourced from public records | 2,770+ jurisdictions, 130M+ permits, 2.3M+ contractor profiles, normalized single schema, "AI-enriched," sub-second responses; SOC 2 Type II certified; explicitly states "All Shovels data is sourced from public government records" ([shovels.ai/solutions/api](https://www.shovels.ai/solutions/api)). | No public free tier found; third-party comparison cites **$599/mo** for API access ([gettradebridge.com/compare/vs-shovels](https://gettradebridge.com/compare/vs-shovels)). | The best *national-coverage, single-integration* answer to "does this job need a permit / has one been pulled at this address" — but likely too expensive for a hackathon unless a trial key is available; confirm trial terms directly at signup before committing a demo to it. |
| **BuildZoom / Gryd (buildzoomdata.com)** | Commercial, sales-gated | 380M+ permits, 25+ years history, 90% of US population — impressive coverage, but the API is described as "advertised... but access is sales-gated with no public spec, auth docs, pricing, or sandbox" (independent API report card: **Grade D**) ([supergood.ai/api-report-card/buildzoom](https://supergood.ai/api-report-card/buildzoom), [buildzoomdata.com](https://www.buildzoomdata.com)). | Enterprise, $500–$2,000+/mo per one comparison ([permitledger.com/blog/building-permit-database-comparison](https://permitledger.com/blog/building-permit-database-comparison)) | **Not realistically obtainable in a hackathon** — no self-serve signup found. |

**Recommendation**: for the demo, pick one Socrata-backed city permit dataset (verify the exact dataset ID live rather than assuming one) as the "real" permit watch, and be explicit in the UI/docs that permit coverage is jurisdiction-limited, not nationwide, in the fixture/demo build.

## 5. Document ingestion (reading a bid PDF)

| Option | Fit | Notes |
|---|---|---|
| **`unpdf`** (npm, UnJS) | **Best fit for a Node/Express backend.** Zero native dependencies, works in Node, Deno, Bun, browser, and edge/serverless runtimes; explicitly positioned as "a modern, actively maintained alternative to pdf-parse," designed for "AI applications that need to summarize or analyze PDF documents" ([github.com/unjs/unpdf](https://github.com/unjs/unpdf), [unjs.io/packages/unpdf](https://unjs.io/packages/unpdf)). ~200K weekly downloads. | `npm install unpdf`; `extractText(pdf, { mergePages: true })` gives raw text in a few lines — fastest honest local option, no external network call, no per-page cost, works offline (fits Sift's "fixture mode must execute without network access" requirement). |
| **`pdf-parse`** | Older, far more widely used (~2M weekly downloads) but depends on `pdfjs-dist`'s optional `canvas` native binding, which **fails to build on serverless/edge runtimes** (Vercel, Lambda) without native build tooling ([chudi.dev/blog/serverless-pdf-processing-unpdf-vs-pdfparse](https://chudi.dev/blog/serverless-pdf-processing-unpdf-vs-pdfparse)). Also flagged by one comparison as effectively unmaintained relative to `unpdf` ([unjs.io/packages/unpdf](https://unjs.io/packages/unpdf)). | Fine if Sift's deployment target is a normal Node container (Railway, per CLAUDE.md) rather than edge/serverless — but `unpdf` has no downside there either, so prefer `unpdf`. |
| **AWS Textract** | Real OCR + structured extraction, per-page billed. Plain text detection ~$1.50/1,000 pages; Forms (key-value) ~$50/1,000 pages; Tables ~$15/1,000 pages; AnalyzeExpense (invoice-shaped, closest to a bid's line-item structure) ~$8–10/1,000 pages ([extend.ai Textract guide](https://www.extend.ai/resources/aws-textract-when-to-use-alternative), [tech42consulting.com AWS IDP calculator](https://www.tech42consulting.com/aws-idp-cost-calculator)). 90-day free tier: 1,000 pages/mo text, 100 pages/mo Forms/Tables/Expense. | Only worth it if Sift is already on AWS for the Strands/AgentCore hero and wants deterministic, non-LLM table extraction; adds real integration/auth work for a hackathon day. |
| **AWS Bedrock Data Automation (BDA)** | Flat per-document pricing (not per-feature-stacked like Textract), positioned by AWS's own IDP cost calculator as "the recommended starting point for most new IDP builds" because of its single-API classify+extract flow ([tech42consulting.com](https://www.tech42consulting.com/aws-idp-cost-calculator)). AWS's own worked example: 100 20-page financial documents cost **$20.00 via BDA** vs **$31.36 via Textract+Bedrock FM** ([aws.amazon.com/blogs/machine-learning/intelligent-document-processing-at-scale-with-generative-ai-and-amazon-bedrock-data-automation](https://aws.amazon.com/blogs/machine-learning/intelligent-document-processing-at-scale-with-generative-ai-and-amazon-bedrock-data-automation)). | Better cost/complexity trade-off than raw Textract if AWS is in scope; still real AWS setup (roles, S3 staging) beyond a same-day Node-only build. |
| **Tavily Extract** | Only extracts from a **URL Tavily can fetch itself** — not a file the user uploads to Sift. | **Wrong tool for this job** unless the bid genuinely lives at a public URL (e.g., a contractor emailed a link to a hosted proposal) rather than an uploaded file, which is the more common real case. |

**Fastest honest same-day path**: `unpdf` in the Express backend — zero external dependency, zero network call, fully fixture-mode-compatible, and it directly satisfies CLAUDE.md's "fixture mode must execute the complete product without network access after installation" constraint in a way that Textract/BDA/Tavily Extract cannot (they all require live network/cloud calls). Reserve Textract/BDA as the optional "live mode" upgrade for scanned/photographed bids where `unpdf`'s pure-text extraction would fail.

## 6. Honesty line — ToS constraints that would make a demo dishonest

- **CSLB (CA) HTML "Instant License Check"**: no ToS explicitly published against automation was found, but it is a form-submission HTML page, not a published API — scraping it is unsanctioned by CSLB even if not explicitly forbidden. The **CSV/XLS bulk downloads are explicitly and officially provided for programmatic use** ([cslb.ca.gov/onlineservices/dataportal](https://www.cslb.ca.gov/onlineservices/dataportal)) — prefer those and say "CSLB bulk data export," never "CSLB API."
- **Florida DBPR / Arizona ROC**: no official API exists at all; every so-called "API" found is an unauthorized third-party scraper of a government HTML search form. Presenting scraped DBPR/ROC data as "verified via official API" in a demo would be dishonest. If used at all, label it "search-assisted, not government-verified."
- **Google Business Profile API**: ToS explicitly **prohibits** using it to manage or pull data for a listing you don't own or have the owner's authorization to manage, and prohibits providing "indirect access" to end-clients who haven't registered their own project ([developers.google.com/my-business/content/policies](https://developers.google.com/my-business/content/policies)). Using it to pull a subcontractor's reviews without their consent would be a **direct ToS violation** — do not build this. Use Google Places API (New) instead, which is designed for exactly this "look up any place" use case, subject to its own caching/attribution rules (see below).
- **Google Places API (New)**: allowed for arbitrary lookups, but (a) content besides the place ID generally **cannot be cached/stored** beyond Google's allowance without a separate agreement, (b) results shown without a map must display the Google logo, and (c) attribution/third-party-provider credit must stay visible and unobscured ([developers.google.com/maps/documentation/places/web-service/policies](https://developers.google.com/maps/documentation/places/web-service/policies)). A demo that silently stores review text in Sift's SQLite forever, or strips Google branding, would be non-compliant — surface it live/short-TTL with attribution instead.
- **Yelp Places API**: ToS explicitly bars using the API "to enable... commercial uses" beyond consumer-facing display, imposes a **launch restriction during the free trial** ("you may not publicly launch or release your product that uses the API" during the trial — [terms.yelp.com/developers/api_terms/20250113_en_us](https://terms.yelp.com/developers/api_terms/20250113_en_us)), and requires Yelp's prior written consent for PR/publicity about the integration. A public hackathon demo video built entirely on trial-tier Yelp data is arguably a "public launch" under §7.3 — treat this as a real constraint, not a technicality, and keep Yelp usage to development/internal demo framing, or budget for a paid tier before a public submission video.
- **BBB / Angi / HomeAdvisor scrapers**: no sanctioned API exists for either; commercial scraping services (Bright Data, ScrapingBee) explicitly market themselves as compliant, but the underlying site terms for BBB/Angi typically prohibit automated scraping of their own content. Do not represent scraped BBB/Angi data as "official" in submission material; Tavily Search snippets with a visible source link are the safer, attributable substitute.
- **Socrata open-data portals (WA L&I, TX TDLR/TSBPE, city permits)**: these are explicitly published as open government data for public reuse — no ToS conflict. This is the **cleanest honesty story** in the whole set: cite the dataset, use an app token, respect the 1,000 req/hour throttle.
- **Shovels.ai**: legitimate, contractually licensed, SOC 2-certified redistribution of public permit records — honest to use if the trial/cost fits the budget; just don't claim it's free.
- **Tavily Search/Extract used as a "reputation" or "verification" substitute anywhere above**: always label results as *search results a human should read*, not as *verified facts* — Tavily is a search layer, not an authority, and presenting its snippets as equivalent to a licensing board's verified status would itself be a form of the dishonesty this section is meant to prevent.
