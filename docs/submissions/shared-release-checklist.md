## Findings from this audit worth reading before submission

These are not new checklist items; they are the concrete, code-verified discoveries behind several of the unticked items above, gathered here so they are not lost in the per-item annotations.

1. **The live, deployed investigation path never calls a real language model, in any environment, with or without AWS credentials — and this is not disclosed anywhere.** `apps/agent/src/runtime/model-provider.ts`'s own header comment states the design intent plainly: "a real `BedrockModel` for live runs … and a deterministic `ScriptedModelProvider` test double for CI." In actual production wiring, that intent is not what happens: `apps/agent/src/runtime/home-energy-engine.ts`'s `runOneInvestigation` (the function `RunService.requestInvestigation` — the same command both the UI's "Investigate" button and the WebMCP `sift_request_investigation` tool call — actually executes) unconditionally builds its Swarm dependencies with `buildHomeEnergySwarmScriptedProviders()`, never `createBedrockModel`. `apps/agent/src/runtime/car-purchase-engine.ts` does the identical thing with `buildCarPurchaseScriptedProviders()` for the Graph pack. `createBedrockModel`/`resolveModel` — the only code that ever constructs a real `BedrockModel` — have zero callers anywhere in `apps/agent/src` outside their own module and its own test file. `docs/specs/strands-runtime.md:292` ("Deterministic tests use a scripted `ModelProvider` test double and never call Bedrock") is worded to imply the converse for non-test runs, which is not true of this deployment. This does not mean the Strands orchestration is fake — the Graph/Swarm, interventions, hooks, and deterministic scoring are all genuinely real and exercised — but the *model* component specifically always replays a fixed two-round script (`round1`/`round2`), and no code path exists today by which supplying AWS credentials would change that for the currently-wired local execution target. Worth an explicit, honest line in the submission docs rather than leaving a reader to infer live model behavior from `.env.example`'s `SIFT_MODEL_ID` variable and `docs/specs/strands-runtime.md`'s current wording.
2. **The README has no product screenshots**, despite the shared checklist explicitly requiring them and real screenshots existing on disk (`artifacts/demo/screenshots/`, 7 files) that could be embedded.
3. **No nonintrusive release/build identifier is displayed anywhere in the deployed product** — not in the UI, not in `/ping`'s response body. A judge has no way to confirm which commit the live site is running without being told out-of-band.
4. **No secret-scanning tool covers git history**, only the current working tree (`scripts/check-source.ts`, run as part of `pnpm verify`'s `lint` stage). There is no `gitleaks`/`trufflehog`/CI workflow of any kind in this repository.
